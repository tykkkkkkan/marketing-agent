1. 产品背景与目标

1.1 业务背景

中渔天下是一家渔具企业，已上线 ZT-agent（C 端 AI 客服 Agent），覆盖顾客咨询、订单/库存/钱包查询与引导转化，沉淀了大量真实咨询与交易数据。当前企业侧（B 端）的运营工作——销售复盘、活动文案、选品与触达决策——仍依赖人工完成，缺少以数据驱动的自动化营销能力。

1.2 产品目标

构建独立的营销自动化 Agent（B 端），面向运营与商家，用大语言模型（LLM）辅助完成：销售分析、营销文案生成、客户分群、活动编排与合规审核，把 ZT-agent 沉淀的顾客咨询与交易数据转化为可执行的营销动作，实现「数据 → 洞察 → 动作」的闭环。

1.3 成功指标（KPI）

  • 运营制作一份营销方案/文案的平均耗时从人工约 30 分钟降至约 3 分钟；
  • 能够基于真实交易数据自动产出「销量榜 / 库存预警 / 退款分析」等看板；
  • 顾客高意向信号（来自 ZT-agent）可在运营后台被自动归集与提醒；
  • 营销动作 100% 经过人工审核后执行，杜绝误触达。

2. 用户角色与使用场景

角色职责典型场景
运营专员看数据、生成文案、编排活动、提交审核周一复盘上周销量，生成「春季钓法主推」朋友圈/私域文案
商家 / 店主查看分群与活动效果，决策是否投放查看「高频咨询未下单」人群，决定是否发放优惠券
系统管理员配置模型密钥、维护知识库、审计日志配置 DeepSeek / 向量库连接，查看操作日志与权限

3. 功能需求

F1 销售分析看板

  • 描述：基于 agent_db 的 orders / wallet_transactions / products / inventory 只读聚合，展示经营概览。
  • 输入：时间范围、品类筛选。
  • 输出：销量榜、GMV、复购率、退款率、库存预警列表。
  • 验收标准：数据来源于真实库表，与后台订单数据一致；响应时间 < 2s。

F2 智能营销文案生成

  • 描述：结合销售洞察与企业知识库，生成面向不同渠道（朋友圈/私域/详情页）的营销文案。
  • 输入：目标商品 / 人群 / 渠道 / 卖点关键词。
  • 输出：多版本文案草稿 + 合规性自检标记。
  • 验收标准：文案不出现虚假数据与违禁词；支持一键重写与微调。

F3 客户分群与画像

  • 描述：由 orders + conversations 聚合出客户画像与分群（高价值 / 流失风险 / 高频咨询未下单）。
  • 输入：分群规则（RFM 或规则表达式）。
  • 输出：分群列表、人群规模、特征标签。
  • 验收标准：分群可解释，规则可配置，结果可导出。

F4 营销活动编排（自动化触达）

  • 描述：基于信号与分群，生成活动方案（目标人群、文案、节奏）。MVP 阶段仅产出草稿并提交审核，不自动外发。
  • 输入：触发条件（如库存预警、高意向信号）。
  • 输出：活动方案草稿（marketing_campaigns）。
  • 验收标准：活动方案经人工审核后才可标记为「可执行」。

F5 客户信号看板

  • 描述：消费 ZT-agent 写入的 customer_signals 事件表，归集顾客高意向 / 流失风险 / 高频问题。
  • 输入：信号类型、时间。
  • 输出：信号列表与趋势。
  • 验收标准：信号与 ZT-agent 写入事件一一对应，可下钻到原对话。

F6 合规审核队列

  • 描述：所有对外文案与活动在执行前进入审核队列，由运营/管理员确认。
  • 输入：待审文案 / 活动。
  • 输出：审核通过 / 驳回（附理由）。
  • 验收标准：未审核内容不可进入执行态。

4. 与 ZT-agent 的协同

  • 数据关联：两后端共用 MySQL 库 agent_db；营销 Agent 对业务表只读，仅写新增的 customer_signals / marketing_campaigns 等表，杜绝与订单/库存事务冲突。
  • 事件信号：ZT-agent 在对话中识别「高购买意向 / 高频问题 / 流失风险」时写入 customer_signals；营销 Agent 定时消费并触发动作，事件表比「直接 API 互调」更稳（可重放、可审计、解耦部署）。
  • 边界：ZT-agent 不调用营销 Agent；营销 Agent 不修改订单/库存/钱包，仅读取分析。

5. 非功能性需求

维度要求
性能看板查询 < 2s；文案生成流式返回，首字 < 1.5s
安全运营后台 JWT 鉴权；密钥走 .env 不入库；对外仅只读 agent_db
可用性单服务故障不影响 ZT-agent；营销 Agent 可独立部署/回滚
合规所有对外内容经人工审核；不生成虚假数据与违禁表述
可观测关键操作留痕（谁、何时、何动作）；LLM 调用可追踪

6. 范围与边界（MVP）

范围内（MVP）：F1 销售看板、F2 文案生成、F5 信号看板、F6 合规审核、只读接入 agent_db、React 运营后台基础版。

范围外（后续迭代）：实接短信/企微/邮件等外部推送渠道；自动 A/B 实验；跨店多租户；实时流式信号消费。

7. 验收标准与里程碑

里程碑目标验收
M1 数据通路FastAPI 只读连上 agent_db，跑通销量榜/库存预警真实数据一致
M2 Agent 内核LangChain Agent + 3 工具（查销量/读知识库/生成文案）能端到端生成一份文案
M3 运营后台React 看板 + 文案草稿 + 审核队列可演示完整闭环
M4 协同闭环customer_signals 联动 + 合规审核信号可触发方案草稿
